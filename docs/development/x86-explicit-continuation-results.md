# Explicit x86 continuation results

`Options.X86TailGroups` remains an explicit assembly-only closed-target
contract. It is not the automatic direct-tail producer or a Go declaration
permission. `GoModuleOptions` has no corresponding producer; an ordinary Go
binding cannot reconstruct this role from helper `func()` declarations.

The existing coalescer supplies the actual root's instructions, labels and
indirect destinations. A request-local seal binds the complete original and
coalesced files, signatures, resolver uses, tables, target and instruction
ordinals. Every derived instruction retains its entire private tuple as well
as its exported source spelling. Copied graph/flow tokens, changed source or
plans fail permanently. Final resolver callbacks are followed by the same
complete guards; no user File is mutated.

Both x86 modes consume that graph through the shared bounded must-state
observer. Every indirect edge includes every named helper, retaining root
GP/vector/FLAGS state and checking all result bytes at every reachable RET.
Initializers share the same request work budget. Helpers never acquire root
signatures, callable entry state or another root's logical frame.

Code targets and table addresses are separate opaque identities, never NUM,
incoming pointers or initialized pointees. Complete private mutable GLOBL
tables have one ordinary void initializer, optional NOPTR only, and complete
full-word code writes at every initializer RET. Calling the initializer before
dispatch remains the existing explicit caller contract, not an inferred fact.
The table's finite values do not enter the numerical BSS/literal directory.
Partial/vector reads, arithmetic, FP/native escape, unknown stores and
unclassified symbol aliases remain Context. A paired ordinary scalar output
store needs its actual incoming Ptr and defined data; it grants no extent or
logical result write, and revokes subsequent possibly aliased table loads.

This bounded code-address consumer admits the existing Linux/Darwin/Windows
AMD64 and Linux/Windows 386 target profiles only. An additional OS/ABI needs
an actual pointer-width observation, not a mnemonic or target-name exemption.
x32, unknown profiles and mismatched source/target words remain Context;
wasm never receives blockaddress. Other numerical translation is unchanged.
CALL, physical SP/BP, raw/native roles, result bool canonicality and independent
numerical/TLS owners do not gain a new contract here.

Portable tests retain the original borrowed-frame and LLVM roots, independent
whole-source negatives, both historical/current Go assemblers and five-target
three-Options-API LLVM IR/backend O0/O2 objects. Native execution is separately
owned by `TestCrossLinuxRuntimeMatrixX86ContinuationWholeCFGOriginalGoAndLLVM`
on Linux/amd64, with original Go and LLVM for both ISAs and memory/register
dispatch. A missing static i386 compiler or kernel execution support fails.
Local Darwin qualification does not certify this native axis.

The existing required physical source-stack numerical runtime owner now
publishes distinct amd64/386 children on native Linux/amd64 without selecting
the unrelated wider cross-runtime matrix. Explicit cross execution retains
its original QEMU route; neither route skips missing required tools.
